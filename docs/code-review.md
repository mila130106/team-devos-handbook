# Чек-лист рецензування (Code Review)

Цей чек-лист використовується при перевірці кожного Pull Request нашої команди. Рецензент має перевірити ці пункти перед тим, як надати `Approve`. На кожне питання можна відповісти лише «так» або «ні».

## Робота з Git
- [ ] Чи відповідає назва гілки конвенції `тип/ім'я-тема`?
- [ ] Чи зведені (squashed) проміжні робочі коміти (на кшталт `wip`, `fix`) в один логічний коміт зі змістовним повідомленням?

## Логіка консольної утиліти
- [ ] Чи обробляються помилкові вхідні дані (наприклад, якщо користувач вказав шлях до файлу, якого не існує)?
- [ ] Чи повертає утиліта коректний код виходу (`exit code 0` при успіху, `>0` при помилках)?
- [ ] Чи виводиться довідка (help) при запуску утиліти з неправильними або порожніми аргументами?
- [ ] Чи відсутні в коді абсолютні шляхи (hardcoded paths), які працюватимуть лише на комп'ютері автора?

## Документація
- [ ] Чи оновлено розділ "Параметри" в README, якщо цей PR додає нові прапорці для команди?
